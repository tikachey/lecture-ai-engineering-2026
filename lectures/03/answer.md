# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  同じ質問「AIE2026の講座の宿題にある「3レベル」とは何ですか？」に対して、第1回の `app.ask`（gemini-3.5-flash-lite）は「基礎→応用→発展の難易度別の3段階」と推測で答え、「どれか1つで完了」「採点しない」は出てこなかった。エージェント（`app.agent`、同じモデル）は先に用語集を検索し、2回とも `data/glossary.json` の homework-levels のとおり「基礎（講義内容の確認）・実装（自分でコードを書く）・発展（調査や試行）のどれか1つに取り組めば完了、原則として採点しない」と答え、最後に「関連する回：第1回」を付けた。
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「3レベル」の質問：`search_glossary({'query': '3レベル'})` の1回
  - 「LoRAとQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回（用語ごとに分けて検索した）
  - 「第2回の内容から確認問題を1問出して」：`make_quiz({'lecture': 2})` の1回
- 1つの質問での LLM 呼び出し回数（`requests`）：
  3つの質問とも `requests=2`。1回目でツールを呼ぶことを決め、2回目でツールの結果を見て回答を書いた。LoRA の質問では1回目に2つの検索を同時に依頼したので、`tool_calls=2` でも `requests` は2だった。入力トークンは「3レベル」1,015、「LoRAとQLoRA」1,428、確認問題 957。
- 追加したツールと、docstring に書いた説明：
  `app/tools.py` に `make_quiz(lecture: int) -> str` を追加し、`app/agent.py` の TODO の場所で `agent.tool_plain(tools.make_quiz)` と登録した。用語集から `lecture` が一致する用語を集めて `random.choice` で1つ選び、`{"question": "「○○」の意味は？", "answer": 定義}` を JSON 文字列で返す。用語が無い回（第0回など）では「第0回の用語は用語集にありません。用語がある回: 1, 2, 3, 4, 6」と返す。docstring は次のとおり。

  ```text
  指定した回（1始まりの整数）の用語から1つを選び、確認問題と答えを返す。

  「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。
  返り値の answer は用語集の定義そのもの。出題するときは question だけを見せ、
  答えは利用者が考えたあとに示す。
  ```

  `--list-tools` で3つ目のツールとして表示され、`uv run pytest -q` は 15 passed だった。実行すると make_quiz が「PEFT」を選び、モデルは答えを伏せたまま「「PEFT」とは何の略で、どのような手法のことですか？」と出題した（ツールが返した問題文を少し言い換えていた）。

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - 自分の PC（Windows 11、`uv run`、gemini-3.5-flash-lite）で、書き換えたあと同じ質問を `--trace` 付きで2〜3回ずつ実行した。試し終わったら元に戻し、commit には make_quiz の追加だけを入れた
  - 実験1：`search_glossary` の docstring の「query には調べたい用語を1つだけ入れる」を「まとめて入れる」に変えた
  - 実験2：`INSTRUCTIONS` から「必ず search_glossary で用語集を確認する」の行を消した。それでも検索したので、検索につながりそうな文をさらに1か所ずつ消していった（2-2：docstring の「…答える前に使うこと」を削除、2-3：さらに INSTRUCTIONS の「用語集に見つからないことは…」「回答の最後に、関係する回（第N回）を示す」を削除）。最後に、用語集に無い一般的な用語「Transformerとは？」でも、元と 2-1 を比べた
- 結果：

  **実験1（docstring「1つだけ」→「まとめて」）**

  | 質問 | 設定 | ツール呼び出し | requests | 入力トークン |
  |---|---|---|---|---|
  | LoRAとQLoRAの違いは？ | 元 | `'LoRA'`, `'QLoRA'` の2回（2回とも） | 2 | 1,428 |
  | 同上 | まとめて | `'LoRA QLoRA'` の1回（3回とも） | 2 | 1,117 |

  - 2語なら、まとめて検索しても1回で両方の定義が返り、回答の中身は変わらず、入力トークンは約2割減った
  - 4語をまとめると、`search_glossary` は最大3件（`MAX_RESULTS = 3`）しか返さないので PEFT・LoRA・QLoRA で枠が埋まり、RAG が落ちた。モデルは RAG だけを検索し直した。2回目はさらに回の要点まで読みにいき、requests が6、入力が約8千トークンに増えた
  - RAG は用語集に無い。`'RAG'` で検索すると、別名「inter-rater agreement」の空白を詰めた文字列が "rag" を含むため、無関係の「一致率」（第4回）が1件目に返った。元の設定では2回のうち1回が「RAGは用語集に登録されていない」と断ったが、まとめた設定の1回目は「第4回（RAGの活用など）で詳しく扱われます」と、誤った検索結果に引きずられた案内を書いた

  **実験2（検索を促す文を消していく）**

  | 設定 | 「3レベル」の質問 | 「LoRAとQLoRA」の質問 | 回答の最後の「関係する回」 | 入力トークン（3レベル） |

  | 元 | 2回とも `'3レベル'` で検索 | 2回とも `'LoRA'`, `'QLoRA'` で検索 | 2回とも「第1回」 | 1,015 |

  - 検索の引数・回数・`requests=2` は、どの段階でも元と同じだった。回答の中身も4段階とも用語集どおりで、「どれか1つで完了」「原則として採点しない」も毎回入っていた
  - 用語集に無い「Transformerとは？」でも、元・2-1 とも2回ずつ、毎回 `search_glossary({'query': 'Transformer'})` を呼んだ（2-1 では途中で1回 503 が出たので再実行した）。見つからなかったあとの答え方は毎回違い、元の1回は「用語集にはない用語です。」の1行だけで終えたが、ほかは一般的な説明を書き、2-1 の1回は根拠なく「関連する回：第3回」と付けた
- 気づき・疑問：
  - 「必ず検索する」と書かなくても、このモデルは「講座の学習支援エージェント」という役割とツールの名前・説明文（「講座の用語集から用語を検索し…」）だけで、毎回検索した。一方、「回答の最後に関係する回を示す」のような出力の形の指示は、消すとすぐに守られなくなった。ツールを使うかどうかは役割と説明文で、回答の形は INSTRUCTIONS で決まっているように見えた。「必ず」の行は、このモデルでは保険の役割だと思う。別のモデルでも同じかは確かめていない
  - docstring の「1つだけ」を「まとめて」に変えただけで、検索の引数と回数がそのまま変わった。モデルは説明文を素直に引数の作り方に反映する。ただ、まとめると呼び出しは減る一方、検索結果の上限（3件）とぶつかって取りこぼし、かえって呼び出しが増える場合があった。説明文は、ツールの実装（件数の上限や照合の仕方）と合わせて書く必要がある
  - 検索ツールの部分一致が、用語集に無い RAG に対して無関係の用語を返し、それがモデルの回答（第4回）にそのまま入った。ツールが「見つからない」を正しく返すことも、指示の書き方と同じくらい回答の正確さに効くと感じた。空白を詰めた別名や定義文への部分一致は、語の区切りを考えて照合するか、関連の強さで並べてから上限で切るのがよさそう
  - 疑問：「用語集に見つからないことは、推測で断定せず『用語集にはない』と伝える」と書いてあっても、見つからなかったあとに一般論を書くかどうかは実行ごとに揺れた。「一般的な説明はしてよいが、回の案内は用語集にある場合だけ書く」のように、してよいことまで具体的に書けば揃うのかを試してみたい
